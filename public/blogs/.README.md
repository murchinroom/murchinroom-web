# source of the blogs.

Put `.md` articles here.

- `public/blogs/[subdir/]name.md` will be rendered to blog page `/blogs/[subdir/]name`.
- `public/blogs/name/index.md` will be rendered to blog page `/blogs/name`.
  - This is preferred, see [conversion](#convention) below for details.

> Reference: https://content.nuxt.com/get-started

## Directory structuring

> Reference: https://content.nuxt.com/usage/content-directory

```
public/blogs/
├── title-sep-by-dash.md
├── ordered/
│   ├── 1.hello.md
│   └── 2.world.md
├── article-with-attachments/
│   ├── index.md  # contains ![](attachments/img.png)
│   └── attachments/
│       └── img.png
└── article-without-attachments.md
```

- The `article-with-attachments/` pattern is preferred, see [conversion](#convention) below for details.

## File content

> Reference: https://content.nuxt.com/usage/markdown

File naming: `short-title-sep-by-dash.md`

```md
---
title: overrides the h1 header
publishedAt: 2024-12-23
---

# Title of the Article

A brief description to the article.

## Content

An article should come with exact one h1: it will be parsed as the article title.

### YAML front-matter

- `publishedAt: YYYY-MM-DD` is required to publish an article. Otherwise, the article will be ignored.
- `title: ...` is optional and not recommended. Use a meaningful h1 `# h1` instead.
```

## Convention

Organization blogs as following:

```
public/blogs/
├── topic-name/
    ├── article-name/
        ├── index.md  # contains ![](attachments/img.png)
        └── attachments/
            └── img.png
```

This is to avoid possible problems about relative paths:

- Assume the article is `subdir/article.md` and its attachments are `subdir/attachments/*.png`
  - Then, the article will be available on both:
    - `/blogs/subdir/article`
    - `/blogs/subdir/article/`
  - Nuxt Content renders the Markdown page into both routes correctly, but not the attachment links:
    - for `/blogs/subdir/article`, a relative link `![](attachments/a.png)` is resolved to `subdir/attachments/a.png`
      - This is the expected behaviors
    - (bug here) for `/blogs/subdir/article/` a relative link `![](attachments/a.png)` is resolved to `subdir/article/attachments/a.png`
      - This may access a not existing file.
- With `subdir/article/index.md` and `subdir/article/attachments/*.png`, this problem is bypassed.
  - The article will still be available on both:
    - `/blogs/subdir/article`
    - `/blogs/subdir/article/`
  - On the both cases, a relative link `![](attachments/a.png)` will be resolved to `subdir/article/attachments/a.png`.
